# AI 相互レビューフロー（Claude ↔ Codex）

Claude と Codex を交互に使った相互レビューの運用ドキュメント。  
「片方の AI で実装し、もう片方の AI でレビューする」往復を、チャットログの手動コピー等なしで回す。

## 前提・登場ツール

| ツール | 役割 |
|------|------|
| Claude（CLI / アプリ） | Claude 側の実装 / レビュー |
| Codex（CLI / 拡張） | Codex 側の実装 / レビュー |
| `codex` / `claude` スタンドアロン CLI | `npm run review:*` から呼ぶワンショットレビュー（拡張 / アプリとは別物） |
| git ブランチ・コミット・PR | 受け渡しメディア |

CLI ブリッジ（`npm run review:*`）を使う場合は `codex` / `claude` が PATH にあること。  
拡張 / アプリ内で完結する分には不要。

## 基本フロー（4 ステップのループ）

実装担当とレビュー担当を入れ替えながら、次の 4 ステップで回す。

1. **実装** — 一方（例: Claude）が作業ブランチで実装し、意図（何を・なぜ）をコミットメッセージに残す。
   これがレビュアーへの受け渡しノートになる。
2. **レビュー** — もう一方（例: Codex）が差分をレビューし、指摘を出す。
3. **指摘対応** — 実装側（Claude）が指摘に対応し、差分とコミットへ反映する。
4. **妥当性確認** — レビュー側（Codex）が「指摘が解消されたか / 新たな回帰が無いか」を**更新後の差分**で確認する。

方向は対称で、次の 2 系統を使い分ける。

- Claude 実装 → Codex レビュー → Claude 指摘対応 → Codex 妥当性確認
- Codex 実装 → Claude レビュー → Codex 指摘対応 → Claude 妥当性確認

各ステップで受け渡すのは **差分（と前ステップの指摘）** であり、チャットログではない。

## 実装完了後の起点（Claude 主導・選択肢の提示）

Claude が実装を完了したら、手で Codex へ切り替えず、Claude が端末から `npm run review:codex*` を実行し、
その出力を読んで後続まで自走できるようにする。Claude は次の 3 択をユーザに提示する。

| 選択肢 | 何が起きるか |
|--------|--------------|
| **A. Codex にレビューを依頼** | Codex は**レビューのみ**（ファイルは変更しない）。Claude が結果を読み、修正を適用する。 |
| **B. Codex にレビューと検出事項の修正を依頼** | Codex が**レビュー + 修正を作業ツリーへ直接適用**する。Claude は Codex の修正内容をレビューする。 |
| **C. 何もしない** | レビューを回さず終了。 |

### A.「レビューを依頼」を選んだ場合

1. Claude が `npm run review:codex` を実行（codex は `-s read-only`、ファイルを変更しない）。
2. Claude がレビュー結果を読み、修正を適用する。**ユーザ判断が要る内容は確認してから着手**する。
3. 修正が完了したら、改めて `npm run review:codex` で妥当性確認（指摘解消 / 回帰なしの確認）。

### B.「レビューと修正を依頼」を選んだ場合

1. Claude が `npm run review:codex:fix` を実行（codex は `-s workspace-write`、検出事項を直接修正）。
2. Claude が **Codex の検出内容と修正差分（`git diff`）・要約をレビュー**する。  
   問題なければ採用、指摘があれば Codex に再修正を依頼するか Claude が手当てする。
3. 構文チェック / lint / テストを Claude が実行して整合を確認する。

> Claude から `npm run review:codex*` を実行する際は、**codex がネットワークを使う**ため、サンドボックス内では
> API 接続が失敗しうる。ネットワーク許可付きで実行すること。

## サーキットブレーカー（無限ループ防止・必須）

レビュー ↔ 指摘対応のループは **最大 3 往復**まで。
**1 往復 = 実装（または前回指摘への対応）→ レビュー → 結果確認 まで**
（= レビュー 1 回とその結果確認で 1 往復。修正が続くかは問わない）。

- カウント対象は **blocker / 要修正**。`提案` は任意適用で、見送ってもループ継続の理由にしない。
- **3 往復しても未解決の blocker / 要修正 が残る場合はループを中断し、サマリを提示してユーザの判断を仰ぐ**。  
  サマリには「残っている指摘（重大度付き）と未解決の理由」「各往復で試したことと結果」
  「収束しない理由の推測」「選択肢（方針変更 / 直接対応 / 見送り別途 Issue 化 / 中止 など）」を含める。
- 同じ指摘が往復をまたいで**揺り戻す**（直すと別の指摘が出て元に戻る等）と判断したら、
  3 往復を待たずに中断してユーザに相談してよい。
- 往復回数は会話内で数える（CLI は 1 回ごとのレビュー実行のみで往復状態を持たない）。

## 各ステップの実際の操作

### 実装

通常どおり実装し、ブランチへコミットする。意図をコミットメッセージ本文に書く。これが受け渡しノートになる。

### レビュー・妥当性確認

対象はどちらも**更新後の差分**なので、同じ手段で実行できる。やり方は 2 通り。

- **拡張 / アプリ内で完結**: レビュアー側ツールに「現在のブランチ（main との差分）をレビューして」と頼む。  
  会話しながら回すならこちら。妥当性確認も同じセッションで頼める（前回の指摘が文脈に残るのが利点）。
- **ワンショット CLI**: 端末から 1 コマンドで回す。

```bash
npm run review:codex                     # 現在のブランチ (main との差分) を Codex がレビュー (read-only)
npm run review:codex:fix                 # 同上 + 検出事項を Codex が作業ツリーへ直接修正 (workspace-write)
npm run review:claude                    # 現在のブランチを Claude がレビュー (read-only)
npm run review:codex -- --uncommitted    # 未コミット差分 (tracked + untracked) をレビュー
npm run review:claude -- --base develop  # 比較先ブランチを変更
```

`--uncommitted` は **未追跡（git 未 add）の新規ファイルも含める**（コミット前チェックでも取りこぼさない）。  
`--fix` は **codex 専用**で、レビューに加えて検出事項を作業ツリーへ直接修正させる（claude 側の自動修正は未対応）。

### 指摘対応

実装側ツールに戻り、指摘（PR コメント or 端末出力）を渡して修正し、再コミットする。

## CLI ブリッジ（tools/cross-review.js）

`git` の差分をレビュアー CLI へ渡すブリッジ。依存追加なし（Node 標準 API のみ・CommonJS）。

- `codex` / `claude` いずれも **自前で差分を取り出し**、「観点 + スコープ + 差分本文 + モード別指示」を
  stdin で渡して汎用 `codex exec`（末尾 `-` で stdin をプロンプトにする）/ `claude -p` を起動する。
- codex のサンドボックスでモードを切り替える:
  - レビューのみ（既定）→ `codex exec -s read-only`（ファイルを変更させない）
  - `--fix` → `codex exec -s workspace-write`（検出事項を作業ツリーへ直接修正させる）
- codex は `-c approval_policy=never` で**承認を never に固定**する（非対話の自走が承認待ちで止まらないように）。
- **専用サブコマンド `codex exec review` は使わない**。codex v0.137.0 で `--uncommitted` / `--base` が
  `[PROMPT]` と排他になり、観点チェックリストを同時に渡せなくなったため、汎用 `exec` + 差分埋め込みに統一した。
- 差分スコープ:
  - 既定: `git diff <base>...HEAD`（ブランチ vs base、既定 base は `main`）
  - `--uncommitted`: tracked（`git diff HEAD`）＋ untracked
    （`git ls-files --others --exclude-standard -z` の各ファイルを `git diff --no-index` で
    new file 差分化。`-z` NUL 区切りで空白入りパスでも壊れない）
- 引数解析・差分生成・プロンプト生成・観点解決は `tests/cross-review.test.js` が担保する。

## 観点チェックリスト（.cross-review.md）

レビュアーへ渡す観点はリポジトリ直下の `.cross-review.md` を単一ソースとして読み込む。  
解決順は `環境変数 CROSS_REVIEW_CHECKLIST（パス）→ <cwd>/.cross-review.md → <スクリプト>/../.cross-review.md → 組み込みの汎用観点（GENERIC_CHECKLIST）`。  
どれも無くても汎用観点で動く（起動時に stderr へ警告）。`CROSS_REVIEW_CHECKLIST` を明示指定したのに読めない場合は、黙ってフォールバックせず警告を出す。

観点を増減したら `.cross-review.md` を更新する。新規プロジェクトへ導入する場合は[.cross-review.example.md](../.cross-review.example.md) を雛形にする。

## PR を共有ログにする

- 実装がまとまったら PR を作る。以降は **PR が共有ログ**になる。
- **指摘・対応・妥当性確認は PR コメントに記録**する（チャット本文だけに残さない）。
- CI（テスト等）が機械チェックを回すので、AI レビューは設計・回帰・互換性などの観点に集中できる。

## メンテナンス

- レビュー観点が増減したら `.cross-review.md` を更新する。
- CLI のスコープ（`--staged` 等）を増やすときは `tests/cross-review.test.js` も更新する。
